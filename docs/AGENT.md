# Agent 对话工作台

启动 `node server.mjs`，在文件库或编辑器中点击 Agent，或按 `Ctrl+Shift+E`。已有服务需重启以加载新的会话接口与模型代理。模型和密钥沿用原有设置；首次使用可从对话顶栏的选项菜单进入模型设置。

## 界面与交互

界面使用独立的 `agw-*` 组件，颜色跟随编辑器全局主题。标题栏的展开按钮可让对话充满窗口，Esc 退出，草稿、对话和生成状态保留。新增内容与菜单使用短过渡，遵循系统的减少动态效果设置。正文不设置最大高度，代码和宽表格在各自容器中横向滚动。用户向上阅读时暂停自动跟随，点击向下箭头回到最新消息。

同一次用户请求的进展、最终正文和操作属于一个回复。操作日志在执行中展开，完成后收起；展开操作可查看原始参数和结果。生成时可继续输入，Enter 将补充放进队列；停止按钮仅停止当前任务。停止和失败均保留正文及已有工具结果，可点击继续。

新对话不会删除旧对话。历史菜单按工程显示已有会话，文件库有独立会话。草稿按会话分别保存。导出 Markdown 位于对话选项中。

## 对话交付、数学与图解

修改或创建工程后，回复内出现一份紧凑的作品交付，包含首屏、名称、页数、放映、编辑和导出。交付绑定完整版本 ID，刷新或重新打开旧会话仍展示当时的源码与素材。停止或失败后保存的作品标为「进度版本」。纯问答不产生作品交付。编辑打开当前工程，放映与导出使用该次交付的版本。

历史版本使用 `/api/projects/:id/versions/:versionId/preview|present|export`。预览 iframe 隔离脚本，版本素材由只读 `files/` 路由提供；不会从当前工程补取后来修改的素材。HTML 导出内联本地图片、常用媒体、CSS、脚本及 KaTeX 字体；远程资源保留外链，仍需要网络。

聊天使用本地 KaTeX 渲染 `$...$`、`$$...$$`、`\\(...\\)`、`\\[...\\]` 及 latex / tex / math 围栏，未结束的流式公式保留可读源码。普通代码围栏不会被公式解析。SVG 围栏显示矢量预览及可展开源码，通过 DOMPurify 和 SVG 元素 / 属性白名单去除脚本、事件、外部资源与 foreignObject。

`deck_insert_math` 和 `deck_insert_svg` 插入知识表达元素，指定 elementId 可更新；编辑器「插入」有对应入口，选中已有公式 / 图解后可重新编辑源码。`fonts_list` 检测本机字体，`deck_auto_fonts` 按内容风格应用标题 / 正文字体，保留公式和 SVG 内的专用字体。输入区独立选择自动 / 低 / 中 / 高思考强度，实际支持范围取决于模型服务。

## 模板和 PowerPoint

「新建」画廊支持保存当前工程为模板、粘贴 HTML 或导入 HTML / ZIP / PPT / PPTX、自定义模板管理及 ZIP 导出。内置模板不可删除，自定义内容在 `data/templates/`，新工程复制素材与原稿状态，不带入聊天和版本历史。

`POST /api/templates` 支持 `{projectId,name,desc}`、`{content,name}` 或 `{fileName,dataUrl,name}`；`PATCH/DELETE /api/templates/:id` 管理自定义模板，`GET /api/templates/:id/export` 下载 ZIP。接口目录中对应 templates.save/update/delete/export。

`POST /api/projects/import` 增加 PPT / PPTX 支持，参数为 `{fileName,dataUrl,pptMode}`、`{sourcePath,pptMode}` 或 `{importId,pptMode}`。对话中的 PPT 附件会暂存原文件，模型可按用户要求转换成独立网页工程并交付。`pptMode=editable` 默认按 OOXML 的实际幻灯片顺序解析文字、图片、基本形状、表格和图表缓存；`faithful` 使用 Windows Microsoft PowerPoint 导出逐页图片。旧版 .ppt 先由 PowerPoint 转成 PPTX。

单文件上限 40MB，最多 300 页。保留 original/source.ppt(x) 和 original/import-report.json。复杂图表会重绘为柱状图，SmartArt、OLE、Office 数学对象、自定义曲线、复杂组合、动画和转场不保证复刻，导入报告会列出差异。外观优先模式不能单独编辑原有文字 / 形状。PPTX 可编辑解析不依赖 Office；旧版 PPT 和外观优先要求本机安装并完成 PowerPoint 首次启动，且没有其他打开的 PowerPoint，以免影响用户文稿。

`npm install` 自动同步本地数学 / SVG 净化依赖到 app/vendor/，不依赖外部 CDN。

## 接口与工具

`app/js/agent/api-catalog.js` 是前后端共享业务目录，服务端通过 `/api/agent/capabilities` 返回同一份目录。Agent 先用 `app_list_apis` 查操作和参数，再用 `app_call_api` 传 `operation`、可选的 `projectId`、`query` 和 `body`。不开放任意 URL，也不把模型调用和聊天写入接口当成业务工具递归调用。

接口覆盖工程、素材、文件、原稿补丁、全局配置、时间线、修改历史、版本快照、导出、预览、模板、示例、技能、设置、模型、导入目录和搜索。当前工程的文件写入使用编辑器保存 / 重载流程。创建、复制、导入和读取工程的结果附带打开链接；画布工具需要先打开目标工程。

编辑器命令由 `app_list_commands` 动态发现，通过 `app_run_command` 调用。会话控制不允许递归执行。只读、可编辑、完全访问三级权限同时限制工具目录及通用分发器内部的实际操作；联网搜索还要求用户开启联网。

元素、页面、动画、主题、代码等专用工具继续通过编辑器 bridge 执行。返回 `opId` 的编辑器修改可以撤回；工程中的文件覆盖和业务修改也可以通过完整版本恢复。全局设置及工程删除不在工程版本恢复范围内。`file_patch` 要求唯一、逐字匹配再替换，避免改丢长文件的其余内容。

## 版本与对话回退

每轮第一次修改工程前自动保存完整快照，完成、停止或失败后保存本轮结束时的状态。只读分析不产生自动版本。修改前快照写入失败时，该次修改不会执行。停止后继续沿用本轮原始起点，并保存新的结束版本。

- 消息旁的「回退到此处」回到本轮修改之前，默认同步回退对话，原问题回填输入框，方便编辑后重新发送。
- 回复下方的「本轮版本」可查看本轮修改前、修改后的状态。
- 顶栏「对话选项 → 版本历史」列出全部版本，支持命名保存当前工程。恢复前列出相对当前工程的文件变化，可选择是否同步回退关联的对话。
- 回退前自动保存当前工程。同步回退对话时，后续完整消息另存为「回退前分支」，可在「对话历史」打开。恢复备份版本也能找回回退前的工程和关联会话。
- 只恢复工程时保留当前会话，并插入工程回退事件，提醒模型重新读取当前工程。历史摘要在同步回退时使用快照中的边界；不会继续沿用未来对话的摘要。

快照覆盖工程内的源代码、素材、原稿、元信息、`.raw-*` 补丁 / 时间线 / 配置及编辑历史。恢复时移除快照之后新增的工程文件，保留会话与版本库。编辑器先排空自动保存队列，恢复后重读画布、编辑历史和原稿补丁基线，避免旧状态覆盖恢复结果。

数据位于工程 `.versions/manifests/` 与 `.versions/blobs/`，使用 SHA-256 校验和内容去重。工程请求串行执行；恢复先校验并暂存全部文件，再交换内容。事务日志允许服务重启后恢复中断的交换。完整快照不按 30 份自动淘汰，长期使用会占用磁盘空间。全局设置、其他工程和被删除的整个工程不能从当前工程版本库恢复。

此前仅保存的 `.versions/*.html` 会作为「旧版 HTML 备份」显示，只恢复 `index.html`，不伪造历史对话关联、素材或补丁。旧对话无法追溯生成当时未保存的完整快照。

接口：`GET/POST /api/projects/:id/versions`，`GET /api/projects/:id/versions/:versionId`，`POST /api/projects/:id/versions/:versionId/restore {rewindConversation}`。Agent 的 `versions.list/inspect/create/restore` 操作可发现和管理工程版本；模型执行恢复时保留对话，同步回退对话由用户通过界面操作。

## 连续对话与故障恢复

- `server/chat-store.mjs` 原子写入会话；默认 `.chat.json` 兼容旧记录，新增会话保存在 `.chats/`。完整消息不按条数裁切。
- `app/js/agent/loop.js` 串行执行修改、先保存工具结果再请求下一步。停止后保留结果，续接不会主动重放已完成的调用。
- `app/js/core/sse.js` 为浏览器和模型代理共用的增量解码器，覆盖分片 UTF-8、CRLF、多行事件和无空行结尾的最后一帧。
- `server/agent-proxy.mjs` 对齐 OpenAI 与 Anthropic 的流式 / 非流式响应，处理参数兼容、心跳、180 秒空闲超时和客户端取消。缺失完成信号会报告不完整响应。
- 长度上限最多自动续写 24 次，连续连接失败最多重试 3 次，一轮任务最多执行 64 轮工具调用。到达边界时明确暂停并保留进度。未完整生成的工具 JSON 不执行。
- 上下文接近模型窗口时分批整理早期记忆；原始对话保留。当前任务无法容纳时给出可见错误。超大工具结果和长附件提供结果 ID，通过 `tool_result_read` 分页访问完整内容。
- 文本、Word、PPT 附件不再按 24,000 字符静默截断。PDF 单次解析最多 30 页，扫描图最多 4 页；未读取范围会显示在附件及模型输入中。

浏览器关闭前的本机备份和定期服务端保存尽量保留进度；磁盘错误、浏览器存储配额或服务不可用会明确提示。续写、记忆和执行质量仍受配置模型能力、上下文窗口及上游可用性影响。

## 验收

```bash
npm run test:agent
npm run test:authoring
npm run qa:agent
```

运行时测试覆盖消息保存、SSE 尾帧、长历史、记忆分块、长附件分页、权限、完整工具结果、断流、续写、停止、显式续接、逐轮快照、分支恢复、二进制素材恢复、去重、损坏保护、事务恢复和项目锁。

浏览器验收使用本地 Chrome、临时端口、独立数据目录和确定性模拟模型，无需真实 API Key。检查真实页面修改及撤回、多轮偏好、自动续写 / 重连、停止 / 继续、补充队列、长回复滚动、会话 / 草稿恢复、附件 / 菜单、深浅色和 375px 布局。产物位于 `output/playwright/agent-workspace-*.png` 和 `agent-workspace-report.json`。

编辑器原有回归为 `npm run qa`，可以用 `WDS_BASE` 指定独立服务、`WDS_SHOTS_DIR` 指定产物目录。`npm run qa -- --agent` 会额外运行新的独立 Agent 验收。

以上为本地模拟服务验收；不代表已测试每一种真实模型端点。
